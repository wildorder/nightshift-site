Nightshift
How it works Quick start GitHub

A control plane for code written by agents.

Plan a program with Nightshift until the choices left are the cheap ones. Then it runs unattended, and nothing lands until Nightshift has verified it.

Run it locally Read the code

A run, watched live in the Studio.

Planned with you

A plan and a contract, written together: the outcomes, the seams, the decisions that are expensive to reverse, and the human steps hoisted to before the run. A deterministic check says when it is ready.

Verified before it lands

Every job works in its own git worktree. An agent saying it is done is not the same as the work being right, so each change is verified on the real head of the branch and lands as a commit Nightshift owns.

Routed and examined by risk

Cheap, well-tested jobs go to cheap models. Risky ones are examined by a different provider's model before they land, and a disagreement ends in a ruling.

Every decision on the record

Each choice is recorded with the alternatives it beat and the commits it produced. Reverse one, and the correction is planned from the record.

Quick start

Node 24, git, and Claude Code or Codex signed in. No cloud account.

git clone https://github.com/wildorder/nightshift.git && cd nightshift
npm ci && npm run build
(cd apps/cli && npm link)

nightshift local        # the control plane and the Studio, on this machine

Then nightshift init in a repository of yours, plan with /plan-program in Claude Code, and nightshift run. The README has the rest.

How it is built

A TypeScript monorepo with its layering enforced by tests, a control plane on AWS in CDK, and every program's contract, decisions and as-built in the repository. Start with the vision, the architecture and the programs.
